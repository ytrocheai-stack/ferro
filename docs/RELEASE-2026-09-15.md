## Rollback

- Conservar las migraciones aditivas; no borrar tablas, datos locales ni corpus.
- Si la nueva publicación falla, restaurar la versión Worker anterior indicada
  arriba y un frontend compatible con su consentimiento, mediante el workflow de
  Pages desde `main`. Conservar también el SHA del nuevo release para auditarlo.
- La restauración completa D1 es recuperación de desastre: sobrescribiría escrituras
  posteriores; no forma parte del rollback normal de código.
- Atención: en esta rama `coachReadinessConfiguration` exige ambos proveedores
  habilitados y el orden `gemini,nvidia` en producción. Cambiar solo esos flags
  provoca configuración incompleta; no prometer rollback de un único proveedor
  mediante flags sin revisar ese contrato. Para una prueba temporal de failover,
  usar el circuito durable y restaurar su estado al terminar.
